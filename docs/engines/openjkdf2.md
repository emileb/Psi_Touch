# OpenJKDF2 (Jedi Knight: Dark Forces II) engine notes

Module `:OpenJKDF2`. Engine-specific detail for Psi Touch; see [`../../CLAUDE.md`](../../CLAUDE.md) for the project overview. The generic porting process is shared in [`docs/porting/`](../../../docs/porting/).

The `:OpenJKDF2` module wraps **OpenJKDF2** (`shinyquagsire23/OpenJKDF2`, a C reimplementation of DF2/MoTS with its own GLES 3.0 renderer). Engine source at `Games/OpenJKDF2/src/main/jni/OpenJKDF2`, a submodule currently pointing at **upstream**; the Android work is on a local `android` branch and still needs a fork (`emileb/OpenJKDF2`) to be pushed to and `.gitmodules` retargeted.

Status: **Phase 1 (build + boot to menu) implemented; `libopenjkdf2.so` links cleanly (`-Wl,--no-undefined`) in a standalone NDK 27 CMake build, not yet built through Android Studio or verified on device.**

Submodule pointers advanced for this work (all to their `origin/master` at the time): `SDL2_OpenTouch` (SDL3 3.5.0 nested checkout), `Clibs_OpenTouch` (needed its SDL3 `Android_JNI_SendMessage` declaration), `AndroidCore_OpenTouch`, `SAFFAL`, `AudioLibs_OpenTouch`, `MobileTouchControls`. `gl4es` was left alone (local checkout is not on `origin/master`). The engine submodules (TFE, OpenJK) were not touched.

## Upstream's own Android port is deliberately not used

OpenJKDF2 ships a standalone Android app (`packaging/android-project`, `cmake_modules/plat_android_arm64.cmake`, a SAF-based in-game installer in `src/Main/InstallHelper.c` + `DocumentProvider`). None of that fits the OpenTouch host, so the port is a separate platform, `cmake_modules/plat_android_opentouch.cmake`, selected with `-DPLAT_ANDROID_OPENTOUCH=ON` from the wrapper `build.gradle`. It still defines `TARGET_ANDROID` (the source-level facts are shared: GLES3 headers in `SDL2_helper.h`, SDL3 window flags in `Window.c`) plus `TARGET_OPENTOUCH` for the few places where the two ports diverge.

Where it deviates from the TFE/OpenJK template:

- **SDL3, not SDL2.** The engine's `Platform/SDL2/` layer is SDL3 API despite the name. `RunInfo.sdlVersion = 3` makes `PsiFragment` launch `org.libsdl.app3000.SDLActivity`; `jni/Android.mk` has `SDL3_ENABLED=1` so `ndk-build` produces `libSDL3.so` from the `SDL2_OpenTouch/SDL-3.x` nested submodule (SDL 3.5.0, `emileb/SDL` branch `SDL3`). Rebuild with `~/Library/Android/sdk/ndk/27.3.13750724/ndk-build -C PsiTouch/psitouch/src/main/jni -B APP_MODULES=SDL3` — like every prebuilt, Gradle never rebuilds it.
- **`main` is really `SDL_main`.** `SDL2_helper.h` includes `<SDL_main.h>` on `TARGET_ANDROID`, which renames `main()` in `src/main.c` to `SDL_main`. `mobile/game_interface.cpp` therefore calls `SDL_main()` from `PortableInit()`. The SDL activity's own `nativeRunMain` looks for `SDL_main` in `libSDL3.so` (not ours) and fails harmlessly; the OpenTouch flow (`SDLOpenTouch.RunApplication` → `NativeLib.init` → `PortableInit`) is what starts the game.
- **Dependencies come prebuilt, none of `lib/` is built.** `config_platform_deps.cmake` skips its ExternalProject builds (SDL, SDL_mixer, OpenAL, zlib, libpng, freeglut, glew) under `PLAT_ANDROID_OPENTOUCH`. The wrapper `CMakeLists.txt` passes `OPENTOUCH_*` paths and the plat file wraps them as the `SDL::SDL` / `OpenAL::OpenAL` targets the rest of the build expects. OpenAL is the `:openal` module (openal-soft 1.24.3), included as the `AL/` dir itself because the engine writes `#include "al.h"`. zlib is the NDK's.
- **No music yet.** `src/Win95/stdMci.c` streams the CD tracks (`MUSIC/1/*.ogg`) through **SDL3_mixer 3.x**, which the app doesn't build. `STDMCI_NULL` (defined by the plat file) routes it down the existing no-op branch it shares with `STDSOUND_NULL`. Phase 2: build SDL3_mixer 3.2.4 static from a submodule and drop the define.
- **No `jkgm` texture packs.** `Platform/GL/jkgm.cpp` is the only libpng consumer, so `TARGET_CAN_JKGM` is off.
- **arm64 only** (`abiFilters = ['arm64-v8a']`, `android-21`). The engine defines `ARCH_64BIT` and upstream's Android target is AArch64 only. The plat file hard-fails on any other ABI. A 32-bit device would find no `libopenjkdf2.so`; there is no runtime guard in the launcher yet.
- **No `-flto`** — same reasoning as Sigma's `:Quake4`. (NDK is the shared `versions.ndk_version`, 27 for the whole app.)
- **Generated globals need Python.** `cmake_modules/precompile_globals.cmake` generates `generated/globals.{c,h}` (COG symbol tables + the embedded `resource/ui` and `resource/shaders` files) with **cogapp** in a venv it creates in the build dir (`python3 -m venv` + `pip install cogapp` — network on first configure). Under `PLAT_ANDROID_OPENTOUCH` the venv is created with `find_package(Python3)`'s interpreter, since Android Studio's Gradle PATH may not include `python3`. Shaders are embedded, so nothing from `resource/` needs to be on the device.
- **Game folder via `--gamepath`.** `OpenJKDF2Launcher.kt` passes the sub-game folder as-is; `PortableInit()` turns it into the engine's own desktop-style override env vars (`OPENJKDF2_ROOT` and `OPENJKMOTS_ROOT` — which one is read depends on `Main_bMotsCompat`, decided later from the assets) and strips it, because `Main_ParseCmdLine()` exits on unknown arguments. `InstallHelper_GetLocalDataDir()`'s Android branch honours the override first (added), else falls back to upstream's `SDL_GetAndroidExternalStoragePath()/jk1`.
- **SAF-backed game folder — the engine's relative paths get a root prefix.** On Android 13+ the app's primary dir is app-private, so the user's `/OpenTouch/Psi/JKDF2` folder is scoped storage and its path is SAFFAL's literal `/[internal]/OpenTouch/Psi/JKDF2` form. `chdir()` into that fails (not a real path) and SAFFAL only matches absolute prefixes, so the engine's `chdir` + relative `fopen("episode/…")` model can't work (the gotcha in Sigma's `docs/porting/gotchas.md`). Fix (all `TARGET_OPENTOUCH`): `stdPlatform_SetOpenTouchRoot()` is called from the override branch and `stdPlatform_ResolvePath()` prefixes relative paths at the choke points — `Linux_stdFileOpen` (every `pHS->fileOpen`), `stdFileUtil_{FindNext,FileExists,RmDir,MkDir,DelFile}` and `stdJSON.cpp` (cvars/binds/registry). Saves/config therefore land in the game folder for now (via SAF); `user_files` redirection is still Phase 2.
- **SAFFAL's `scandir()` has no `.`/`..` entries** (and ignores `compar`). Upstream's POSIX `stdFileUtil_FindNext` assumes they fill `namelist[0..1]` and starts at index 2, so with exactly two GOBs in `resource/` it found none → "ERR_CANNOT_LOAD_FILE ui\sft\small0.sft". The `TARGET_OPENTOUCH` branch skips whatever dot entries exist instead (and keeps `isNotFirst` as index+1 so it is never 0). SAFFAL does wrap `open/fopen/stat/access/mkdir/remove/rename/opendir/readdir/scandir`, so listings work once that's fixed.
- `InstallHelper_AttemptInstallViaSAF()` returns 0 immediately under `TARGET_OPENTOUCH`: its JNI targets `org.openjkdf2.app.InstallHelperSAF`, which doesn't exist here. It is only reached when required GOBs are missing, which the launcher's file check prevents.
- **Clibs' SDL3 path needs an `extern "C" SDL_Window* window`** from the engine (`touch_interface_base.cpp` passes it to `SDL_StartTextInput/StopTextInput`). Defined in `mobile/game_interface.cpp`, assigned in `Window_RecreateSDL2Window()` right after `SDL_CreateWindow` under `TARGET_OPENTOUCH` (the engine's own `displayWindow` is recreated on every mode change).
- The engine's headers have no `extern "C"` guards of their own (only `types.h`/`jk.h` do internally), so `game_interface.cpp` wraps `Main/jkSmack.h` + `Main/jkMain.h` in `extern "C" {}` — otherwise `jkSmack_GetCurrentGuiState()` is looked up mangled and the link fails.
- **Logging.** The engine prints through `printf`; `game_interface.cpp` redirects stdout/stderr into logcat (tag `OpenJKDF2`) and `LogWritter` via a pipe pump thread (copied from Sigma's AVP). `stdPlatform_Printf()`'s own `LOGI` is disabled under `TARGET_OPENTOUCH` to avoid double lines.
- **Touch layer:** `mobile/touch_interface_openjkdf2.cpp` is the TFE layout minus DF-specific panels; `ENGINE_NAME="openjkdf2"`, `USE_SDL3` for the shared `touch_interface_base.cpp`. Menus are tap-to-position (`MouseMoveAbsolute` + click). `PortableGetScreenMode()` first asks `jkGuiRend_IsMenuActive()` (added accessor over `jkGuiRend_HandlerIsSet`, the count of GUI menus currently owning the draw/message handlers) → `TS_MENU`; this is what catches the post-load "OK" dialog and the escape menu, which appear while the game mode is already `JK_GAMEMODE_GAMEPLAY`. Otherwise it maps `jkSmack_GetCurrentGuiState()`: `JK_GAMEMODE_GAMEPLAY` → `TS_GAME`, the video/cutscene modes → `TS_BLANK`, everything else → `TS_MENU`. Menu keys go through `SDL_PushEvent` (public, thread-safe). Gameplay input is a Phase 2 item — `sithControl` has a bindable action table, so drive that rather than synthetic keys.
- The wrapper only needs the engine's vendored `3rdparty/json`; none of the `lib/*` submodules should be initialised.
- CMake: `CMAKE_SOURCE_DIR` → `PROJECT_SOURCE_DIR` in the engine's `CMakeLists.txt` (module path, `3rdparty/json`) so it works under `add_subdirectory()`. The `PLAT_*` selection is via cache vars, so pass `-DPLAT_ANDROID_OPENTOUCH=ON` from Gradle rather than `set()`ing it in the wrapper.

## Game data

Run dir `/OpenTouch/Psi/JKDF2/` — the game folders go **directly** in there (`Episode/`, `Resource/`, `MUSIC/`), same layout as TFE, not in a sub-folder (launcher `SUB_DIR = "JKDF2"`, `subDir ""`). Detection checks the engine's own required list in the case a Steam/GOG install has: `Episode/JK1.GOB`, `Resource/Res1hi.gob`, `Resource/Res2.gob`, `Resource/JK_.CD`. `Utils.checkFilesInPath` matches file *names* case-insensitively but the directory part must exist as written on SAF storage (primary `/sdcard` is case-insensitive anyway); the engine opens everything case-insensitively via `fcaseopen`. MoTS data is auto-detected by the engine from the GOB magic (`jkRes_ReadKeyRawEarly`), so a MoTS folder should work through the same entry; a dedicated "MoTS" `GameEngine` entry with `-motsCompat` is a follow-up.

Placeholder icon: `res/drawable-xxhdpi/jkdf2_icon.png` is a copy of the Jedi Academy icon.

## Gameplay input (Phase 2)

The engine reads every gameplay action per *input function* (`INPUT_FUNC_*` in `types_enums.h`) through `sithControl_GetKey()` (held + press count, like `stdControl_ReadKey`'s `aKeyPressed`), `sithControl_GetKeyAsAxisNormalized()` / `GetKeyAsAxis()` (key-driven axes: movement, turn keys — a held key reads as 1.5 under `QOL_IMPROVEMENTS`) and `sithControl_GetAxis()` (raw mouse axes). That is the rebind-proof injection point: under `TARGET_OPENTOUCH` those functions add the touch state via three hooks implemented in `mobile/game_interface.cpp` — `OpenTouch_TouchGetKey(func, &presses)`, `OpenTouch_TouchGetAxis(func)` (-1..1, 1 = a held key) and `OpenTouch_TouchBeginFrame()` (called from `sithControl_ReadControls()`, engine thread; latches the press counts, drains the mouse-look accumulator and the pending force-power selection).

- **Movement**: `PortableMove*` → `INPUT_FUNC_FORWARD` / `SLIDE` (the base's strafe is +left, `SLIDE` is +right). Digital dpad buttons override the stick.
- **Look**: mouse mode → `MouseMove()` per input read (Clibs' SDL3 mouse injection → `Window_lastXRel` → the player's own mouse bindings/sensitivity/invert apply; `LOOK_MOUSE_*_SCALE` = TFE's numbers). Joystick mode → `TURN` / `PITCH` key-axes (`TURN` +1 = left, `PITCH` +1 = up).
- **Buttons**: fire/alt → `FIRE1`/`FIRE2` (held, the weapon cog gets ACTIVATE/DEACTIVATED), use → `ACTIVATE`, jump, crouch (`DUCK`, plus a toggle), run (`FAST`, or `SLOW` when the game's own "always run" option is on — `PortableSetAlwaysRun` toggles that option, `sithWeapon_controlOptions & 2`), strafe modifier, weapons 1-9/0 → `SELECT1..0` (0 = lightsaber slot, also the weapon wheel's 10th segment), next/prev weapon, items prev/use/next → `PREVINV`/`USEINV`/`NEXTINV` (grid on `KEY_SHOW_INV`), map (`MAP`, zoom `INCREASE`/`DECREASE`), camera (`CAMERAMODE`), quick save (`GAMESAVE` — there is no quick-load function), centre view, gamma, chat.
- **Force**: use / next / prev → `USESKILL` / `NEXTSKILL` / `PREVSKILL`. The pop-up panel (`KEY_SHOW_FORCE`, mirrors the OpenJK module) has all 14 JK powers; a button queues `sithInventory_SelectPower(player, SITHBIN_F_*)` for the engine thread and holds `USESKILL` while pressed (grip/lightning are hold-to-use). Powers with no JK2/JK3 constant got new ones in Clibs `port_act_defs.h`: `PORT_ACT_JK_FORCE_{JUMP,BLINDING,DESTRUCTION,DEADLYSIGHT}` (240-243). `PortableGetForcePowerKnown()` reads `aItems[bin].state & SITHINVENTORY_ITEM_AVAILABLE` to dim unavailable powers. Icons are reused from the JK2/JK3 set (jump/flashlight/f_dk_rage/f_dk_drain stand in for Jump/Blinding/Destruction/Deadly Sight).
- Menu navigation and the console (`` ` ``) stay on synthetic SDL keys — the GUI reads raw keys.

## Frame rate and the resolution scaler

Measured on a Galaxy Note 8 (Mali-G71, 2220×1080) with `dumpsys SurfaceFlinger --latency`: presented frames at full resolution alternate 33/33/16 ms — the engine's frame is just over one vsync, so vsync snaps it between 30 and 60 fps, which reads as judder. There is no `glFinish`/`glFlush` anywhere (engine, touch layer, SDL fork). The engine renders its scene into an FBO sized from `Window_xSize × jkPlayer_ssaaMultiple` (`r_ssaaMultiple`, default 1.0), i.e. the full window.

The fix is the app's shared framebuffer scaler (`ResolutionOptionsWidget`, `RunInfo.frameBufferWidth/Height`, default "Screen / 2"). Two engine changes were needed for it (`TARGET_OPENTOUCH`):

- **The scaler's FBO is what gets shown, and it is bound after every swap.** `std3D` captured `GL_FRAMEBUFFER_BINDING` once at init (0) as its "window" FBO and composited the scene there — invisible once the scaler is on. `std3D_StartScene()` now re-reads the binding each frame (nothing of the engine's is bound at that point) and refreshes both `std3D_framebuffers[].window.fbo`.
- **SDL still reports the real window size.** Neither SDL fork knows about the scaler; the AVP precedent is to read Clibs' `game_screen_width/height` globals. `Window_ApplyOpenTouchSize()` (Window.c) overrides `Window_xSize/ySize` (pixel size → FBOs, composite viewport) with them after every `SDL_GetWindowSizeInPixels`, while `Window_screenXSize/YSize` stays the SDL window size so the menu mouse mapping (`Window_HandleMouseMove`, 4:3 pillarbox maths) and mouse sensitivity remain in real screen space. Without this the composite was a 2× zoomed quadrant.

`r_fpslimit` (`TICKRATE_MS` in `jkMain.c`) is a real cap and could back a "30 fps" option for devices that still can't hold 60.
